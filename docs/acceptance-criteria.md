# Acceptance Criteria & Traceability Matrix

Per the **AC-Traceability Rule**, every acceptance criterion is referenced by at least one test or
committed evidence artifact carrying its `AC-NN` identifier. Every test docstring in `tests/` opens
with its AC identifier, so `pytest -v -k AC` and `grep -r "AC-07" tests/` both resolve.

Run `pytest -v` to execute the whole matrix. Evidence paths are regenerated by `./run.sh`.

---

## 1. Functional acceptance criteria

> The system is built on LangGraph with an explicit typed state object (TypedDict / Pydantic) shared
> across nodes.

| | |
| --- | --- |
| **Implementation** | `src/discharge_copilot/state.py` — `DischargeState` (TypedDict, `total=False`) with Pydantic sub-models and reducer-annotated accumulator fields |
| **Test** | `tests/test_ac01_typed_state.py` |
| **Evidence** | `evidence/traces/case_001.jsonl` — every node entry/exit records the typed state delta |

**Testable assertion:** `DischargeState` is a `TypedDict`; every worker output field is typed as a
Pydantic `BaseModel` subclass; accumulator fields carry an `Annotated[..., reducer]`.

### AC-05 — Checkpointer enables pause / resume

> A checkpointer persists graph state so a discharge case can be paused and resumed.

| | |
| --- | --- |
| **Implementation** | `src/discharge_copilot/graph.py` — `SqliteSaver` over `.state/checkpoints.sqlite`, `thread_id = case_id`, `interrupt_before=["pharmacist_review"]` |
| **Test** | `tests/test_ac05_checkpoint_resume.py` |
| **Evidence** | `evidence/transcripts/ac05_pause.md`, `evidence/transcripts/ac05_resume.md`, `evidence/logs/ac05_checkpoint_resume.log` |

**Testable assertion:** pause and resume run as **two separate OS processes**. Process A halts at the
interrupt and exits; process B is launched fresh, loads the checkpoint by `thread_id`, and completes
the case. State written before the pause is present after the resume.

**A sharp edge worth knowing about.** Because `thread_id = case_id`, re-running a case that already
completed *resumes* it — the supervisor sees every workstream marked complete and finalizes
immediately. That is correct resume behaviour, and exactly wrong when the intent was to run the case
again. `run --fresh` discards the checkpoint first, and
`test_ac05_clear_thread_discards_a_completed_run` pins the behaviour as a regression test.

### AC-07 — Cross-session memory persistence *(deterministically scored)*

> Memory persists across sessions: a committed test starts a new session and shows recall of
> prior-session facts; its output log is committed.

| | |
| --- | --- |
| **Implementation** | `src/discharge_copilot/memory/episodic.py` + `semantic.py` (SQLite + Chroma, both on-disk) |
| **Test** | `tests/test_ac07_cross_session_memory.py` |
| **Evidence** | `evidence/logs/ac07_cross_session_persistence.log` |

**Testable assertion:** session 1 writes facts (penicillin allergy; caregiver is daughter Maya) and
tears down every handle. Session 2 runs as a **real subprocess** — a separate Python interpreter
with no shared objects — and retrieves both facts. The subprocess boundary is the point: it makes
in-memory caching impossible as an explanation.

### AC-08 — Memory eviction / importance policy

> A memory eviction / importance policy (TTL, LRU, or importance-weighted) is implemented and
> documented.

| | |
| --- | --- |
| **Implementation** | `src/discharge_copilot/memory/policy.py` |
| **Documentation** | [`memory-design.md`](memory-design.md) |
| **Test** | `tests/test_ac08_eviction_policy.py` |
| **Evidence** | `evidence/logs/ac08_eviction.log` |

**Testable assertion:** effective importance = `base_importance × recency_decay + access_boost`.
Entries below the importance floor past their TTL are evicted; each namespace is capped, evicting
lowest-importance-first. Clinically critical facts (allergies) survive; incidental ones do not.

> An agentic-RAG tool is available and the agent decides when to call it for discharge-protocol and

| | |
| --- | --- |

### AC-12 — Reflection / self-healing loop

> The system implements a reflection or self-healing / fallback loop (e.g., re-plan on tool failure
> or low-confidence output) with an evidenced trace.

| | |
| --- | --- |
| **Implementation** | `src/discharge_copilot/nodes/reflection.py` + `route_after_reflection` in `graph.py` |
| **Test** | `tests/test_ac12_reflection_selfheal.py` |
| **Evidence** | `evidence/traces/case_003_selfheal.jsonl`, `evidence/traces/case_003_faultinject.jsonl` |

**Testable assertion:** the critic returns `Reflection(confidence, issues, action)` with
`action ∈ {accept, revise, escalate}`. Two distinct healing paths are evidenced:
1. **Low-confidence output** — the worker is re-run with the critic's issues appended.
2. **Tool failure** — `--fault-inject mcp_timeout` forces a genuine MCP timeout; the run degrades to
   a local fallback and still produces a usable packet.

Both traces come from real forced failures, not from a described-but-untriggered code path.
